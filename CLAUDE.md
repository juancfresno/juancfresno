# juancfresno.vercel.app

Personal portfolio for Juan C. Fresno, deployed at juancfresno.vercel.app.

## Stack

- **Next.js 16** (App Router, Turbopack), React 19, TypeScript.
- Package manager: npm (`package-lock.json`).
- Fonts: Fragment Mono (`next/font/google`, one weight: 400 + italic, `--font-fragment-mono`) for UI text, Switzer (self-hosted via `next/font/local`, files in `src/fonts/switzer/`) for body text. Fragment Mono has no bold: emphasis is colour, chips or underline.
- Visual source v1.0: Figma page "↪ Visual v1.0" (6877:1444), handoff in `refs/visual-v1-figma.md` (frames, components v1/case-top, v1/close, v1/section-head, v1/index-row, v1/pending). Extra tokens from it: `--c-stage` (media stages), `--c-faint`, `--c-g` (G blue).
- Languages: **English at `/`** and **Spanish under `/es`** (same slugs), see **Languages (i18n)** below. Copy sources: `refs/copy-web-v1.md` (EN) and `refs/copy-web-v1-es.md` (ES, with the UI strings table and the language decisions), both by Comercial y marca, 8 Nov 2026, implemented key by key in `src/content/i18n/*`.
- `@vercel/analytics` wired into the root layout (`<Analytics />` in `src/app/[lang]/layout.tsx`).

## Languages (i18n)

No i18n library: a small typed setup (Next 16 App Router pattern: one root layout per locale in `app/[lang]`, a proxy for the unprefixed default).

- **Routing.** Every page lives in `src/app/[lang]/(site)/…`; `src/app/[lang]/layout.tsx` is the root layout (`<html lang="en|es">`, `generateStaticParams` = en, es, so everything stays static). `src/proxy.ts` rewrites English URLs to `/en/…` internally (`/work` → `app/[lang=en]/work`), serves `/es/…` as is, and 308-redirects any public `/en/…` to the bare path (og-image routes excepted). Unknown paths → `app/[lang]/[...rest]` → `app/[lang]/not-found.tsx` (client, localized via context). The proxy skips `/api`, `/_next`, `/_vercel`, files with an extension and `/medida`, `/glyf` (static HTML rewrites); the FDS logic (fds.juancfresno.com + `/FDS` redirect) runs first, unchanged.
- **Slugs.** Same in both languages (copy decision 2). `SEGMENTS` in `src/i18n/config.ts` maps a first segment per locale if Spanish ever gets its own (`/es/proyectos`): one line there, the proxy rewrites it back. Always build links with `localePath(locale, '/work/…')` (server) or `useHref()` (client); never hard-code `/es`.
- **Default and memory.** No `Accept-Language` redirect (copy decision 3: crawlers and shared links get the URL they asked for). The selector sets cookie `lang` (1 year) + `localStorage.locale`; the proxy reads it only on `/`: `lang=es` → `/es`.
- **Selector.** `components/ui/LocaleSwitch` ("ES / EN", fixed order, mono, same pattern as the theme toggle, right after it in the header on every breakpoint). Real `<a hreflang lang>` links to the same page in the other language; a click saves the choice, keeps `?query#hash` and calls `navigate()`. In `providers/PageTransition` a change of locale = the full-screen wireframe cover, then a full page load (another root layout); `providers/langSwitch.ts` (inline head script + sessionStorage flag) keeps `<main>`, header, tab bar and footer hidden on arrival until the provider reveals it with the same effect (3 s safety net; bfcache restores drop the cover).
- **Content.** `src/content/i18n/`: `site.en.ts` / `site.es.ts` (`SiteDict`: META, HOME, INTROS, CLOSE, CONTACT, LAB…, ABOUT, NOT_FOUND, PERSON), `cases.en.ts` / `cases.es.ts` (`WorkDict`: index rows by slug, ARCHIVE, CASES; the ES archive is the EN rows through a vocabulary map), `ui.en.ts` / `ui.es.ts` (`UiDict`: every label, button, aria and HUD string; functions for strings with values). The ES files are typed with the EN shape, so a missing key fails `tsc`; neutral fields (Behance links, note coordinates, photos) come from EN by spread. Access: `getSite(l)`, `getUi(l)` (`@/content/site`), `getProjects(l)`, `getCases(l)`, `getArchive(l)`, `getArco(l)`, `getFeatured(l)`, `toRow(l, p)`, `creditsLine(l, slug, c)` (`@/content/cases`; personal projects by the `personal` flag, not by text). Client components: `useLocale()`, `useUi()`, `useHref()` from `@/i18n/client` (provider in the layout). Server pages: `const l = await localeOf(params)` (`@/i18n/server`, 404 on an unknown locale). Client bundles import `@/content/ui`, `@/content/socials`, `@/content/person` (not `site.ts`, which carries the page copy).
- **To add or edit a string:** page copy → the same key in `site.en.ts` and `site.es.ts` (or `cases.*`); interface text → `ui.en.ts` + `ui.es.ts`. New key in EN only = tsc error until ES has it. Line breaks that matter are explicit `\n` (close headline, case close) or `\u00a0` (ES role keeps «y» with «diseñador»).
- **Visibility.** `copyEn` on a case still decides whether Context/Decisions render, per locale (only Shoeciety today in both); the Spanish text is stored for the 13 v1.0 cases until Juan decides (the 17 Behance imports have no context/decisions yet).
- **SEO.** `pageMeta({ locale, path, … })` (`lib/seo.ts`): canonical per locale, hreflang `en` / `es` / `x-default` (→ EN) on every page, `og:locale` + `og:locale:alternate`. Sitemap lists both URLs of every page with `xhtml:link` alternates. JSON-LD `Person` per locale (same `@id`, `knowsLanguage`), `CreativeWork` with `inLanguage`. OG cards per locale (`lib/og.tsx`, `defaultOg(l)`, `caseOg({ locale })`). `llms.txt` stays English with a line pointing to `/es`.
- **Mobile.** Spanish nav labels are longer: at ≤ 480 px the header clock hides (time stays on Contact and the close), the left cluster gap tightens, and Spanish tabs (and English below 360 px) use tighter pills so the six fit at 320 px. «Proyectos» on /es/work uses a smaller giant size so it never breaks.

## Page margin and grid (single token)

ONE proportional page margin for header/footer chrome AND content, defined once in `globals.scss` `:root`: `--m: max(20px, 2.381vw)` (40 at 1680, ~61 at 2560, 20 at 390; Juan, 10 Nov 2026) and `--gutter: max(12px, 0.952vw)` (16 at 1680; forced to 12px ≤ 768). **The layout is liquid: no max width anywhere** (the old `$page-max` 1680 cap and centring are gone; content and chrome span the full viewport at every width; typography is unchanged and does not scale with the viewport yet). Sass: `$m` / `$gutter` in `_variables.scss` point at those vars. The `container` mixin (`_mixins.scss`) is the only place that applies it (`width: 100%`, `padding-inline: max(var(--m), safe-area)`); the G `GridOverlay`, Nav, Footer, Arco, feed HUD/zoom and Shortcuts all read the same token, and the feed canvas mirrors it in JS (`gridMetrics` in `feed/canvas/layout.ts`: margin `max(20, 0.02381·W)`, gutter `max(12, 0.00952·W)`, 12 at ≤ 768, so keep both in sync). Grid: 12 cols desktop, 4 cols ≤ 768. Never hard-code a page margin (40 / 24 / 20 px) in a component: use `$m` (margin) or `$gutter` (column gap) so the overlay stays true.
Type does not scale up above the design size (Juan, 10 Nov 2026): sizes may shrink on small screens via existing clamps, never grow beyond the 1680 values.

**Social hover clips.** `components/ui/SocialPreview` (one global instance in `layout.tsx`) is ONE shared 256×160 preview for every link with `data-social="<id>"` (footer wordmarks via `GlitchSocialIcon social={id}`, `ContactBlock` text links via `SOCIALS[].id`). The clip is drawn on a `<canvas>`; the DOM only gets transform/opacity, one rAF loop. Entry (Lab 004 · 02 Despixelado, chosen by Juan): blocks of 32 css px pop in at random (hash threshold on `p·7`), then the block size halves per step 32 → 16 → 8 → 4 → 2 → 1 (device px = css × dpr) until the clip is sharp; each block is the mean colour of its area (mip chain of the cover-fitted frame by halving, drawn into a tiny canvas of size/block and scaled up with `imageSmoothingEnabled = false`; 2D canvas only). 520 ms linear in; exit = the same timeline mirrored (338 ms = 520 × 0.65); reversing mid-way continues from the current step. No scan line. Moving to another network the same preview travels on a spring (k 380, ζ 0.62, slight overshoot), skews with its own velocity (≤ 9°) and swaps the clip with a quick re-pixelate (240 ms: old clip 1 → 2 → 4 → 8, new clip 8 → 4 → 2 → 1, 40 ms per step; replaced the Bayer dissolve). The frame line is drawn only over painted pixels. Per-entry sizes are kept (Valencia 224 × 400 vertical). Over a link it follows the cursor horizontally (65 % towards the cursor from the link centre) and sits anchored above the link row (below if there's no room), so it never covers the row; keyboard focus anchors it centred. Mono label chip under it: `BEHANCE ↗ @juancfresno · 03/05` (index within the row; handle from the link's URL), scrambles on change. Leaving a link waits 110 ms for the next one before hiding; Esc, blur, scroll, any outside click or a route change hides it. Files: `public/social/<id>.{webm,mp4,jpg}` (640×400, ~5 s loop, no audio); map in `SOCIAL_PREVIEWS` (`src/content/site.ts`). No bytes until the first hover (a network's video + poster load on its first activation and stay, in a hidden pool); touch / `hover: none` = nothing; reduced motion = poster only, instant in/out, no spring, skew, mosaic or scramble. Timings are the `T`/`SPRING` constants at the top of the file (`T.in`, `T.outRatio`, `T.swap`; `START` = first block). To replace a clip: drop the three files in `public/social/` and keep its `SOCIAL_PREVIEWS` entry (a poster alone shows the still). Networks without an entry show nothing.

**Themes.** Dark (default) and light. Colors are CSS custom properties (`--c-*`, defined in `globals.scss` under `:root` and `:root[data-theme="light"]`); the Sass `$color-*` tokens point at them, so never use `rgba($color-*, …)` — add a new `--c-*` var instead. v0 added `--c-text-hi` (heading tint), `--c-text-dim`, `--c-line`, `--c-line-hi`, `--c-overlay` (chips over images). **Site transition.** `src/providers/PageTransition.tsx` owns `navigate` and runs the page transition: it catches same-origin left clicks on any `<a>`/`<Link>` (capture on `window`, which also records the click's `clientX`; skips modifier keys, `target`, `download`, `data-no-transition`, same-path hash/query links and file URLs), then cover → page theme + `router.push` under the cover → wait for the new pathname (hard cap 3 s) + 2 frames → reveal → focus the new `h1` (or `main`) with `preventScroll`. The effect lives in `src/components/transition/effects.ts`: one fixed `<canvas>` over the **whole viewport** (`SiteTransition.module.scss`: inset 0, 100dvh, z 450 = above nav/tab bar, footer and the G overlay, under `$z-cursor`; `pointer-events: auto` while visible). Reveal: new sections measured, boxes travel FLIP (280 ms expo-out, ≤ 40 ms total stagger), matched by kind (head / text / media / index) then IoU and distance; leftovers collapse into the nearest gutter line (width → 0), new boxes grow out of one; +200–320 veil and boxes fade, lines leave upwards through the header (100 ms). ≈ 560 ms + route wait (Home → Work measured 620 incl. a 40 ms wait). **Sections** (`collectSections`): `main [data-wf]` (value = kind, default media; the Arco view and the feed canvas carry `data-wf="media"` even though aria-hidden) and any visible element ≤ 45 % of the screen tall as one block (taller wrappers open into their children), hugged to its text runs and media, snapped to the column edges (x0 ≤, x1 ≥) and y to 8 px, merged when they overlap or share columns ≤ 24 px apart (≤ half a screen tall; text never merges into media under it), then the closest pairs merge down to the cap. ## Styling system

**CSS Modules + SCSS** — no Tailwind, no CSS-in-JS. Every component's styles live in a sibling `Component.module.scss` file.

- `src/styles/_variables.scss` — design tokens ($color-*, $font-*, $space-*, $fs-* fluid type scale, breakpoints, motion durations/easings, z-index scale).
- `src/styles/_mixins.scss` — `respond-to()`/`respond-min()` breakpoint mixins, layout/typography/visual helpers.
- `src/styles/globals.scss` — resets, custom scrollbar, selection color, Lenis smooth-scroll classes.
- Import convention: `@use '../../styles/variables' as *;` (relative path depth depends on component location) — no path alias in Sass, only in TS (`@/*` → `src/*` in `tsconfig.json`).

## ElasticLine

`src/components/ui/ElasticLine/ElasticLine.tsx` — an interactive divider: an SVG line that deforms toward the cursor with spring physics on hover/proximity and eases back on release (rAF-driven, no dependencies). Renders `stroke="currentColor"`, so its color is set by the parent's `color` CSS property.

This is the **only** divider implementation in the app — every horizontal rule in the UI (nav bottom border, footer top border, section rules in `V0Section` and the case modules) is an `<ElasticLine />`, never a static `<hr>`. Reuse it for any new divider rather than adding a plain line. Exception: the row separators inside tables/indexes (Work index, Lab and experience rows, feed session headers) are CSS borders, since dozens of animated lines per page would be heavy.
